# Техническое задание (ТЗ) для ИИ-агента Antigravity
## Проект: Telegram Metadata Bot (Core Bot ➔ Local Windows Executable)

---

## 1. Общие сведения и цель проекта

**Название проекта:** `Telegram Metadata Bot`  
**Цель разработки:** Создание инструмента для автоматической подмены цифровых отпечатков медиафайлов (фото и коротких видео) под заданные географические координаты и кастомные модели мобильных устройств.

**Стратегия реализации (двухэтапная):**
* **Версия 1.0 (MVP, CLI-бот):** Чистый асинхронный Telegram-бот на Python. Запускается из консоли/терминала, содержит всю бизнес-логику работы с метаданными и хранением состояния.
* **Версия 2.0 (Desktop EXE):** Добавление легковесной графической оболочки (GUI на Tkinter) с кнопками «Старт / Стоп», полем ввода токена и окном логов. Упаковка всего проекта вместе с зависимостями и бинарными утилитами `ffmpeg`/`ffprobe` в автономный исполняемый файл `.exe` для Windows (без необходимости установки Python конечным пользователем).

---

## 2. Архитектурный принцип: подготовка v1.0 к переходу в v2.0

Чтобы при переходе к версии 2.0 не переписывать код бота заново, архитектура с первого дня должна быть **строго модульной**:

```text
[ Telegram Bot Logic & Handlers ]  <───>  [ Metadata Engine (EXIF / FFmpeg) ]
                ▲
                │  (управление жизненным циклом и передача логов)
                ▼
  [ Phase 1: main.py (CLI) ]  ИЛИ  [ Phase 2: gui_app.py (Tkinter + Threading) ]
```

1. **Изоляция движка метаданных:** Модули работы с EXIF и видео не должны знать о Telegram и UI. Они принимают входной путь, параметры подмены и отдают путь к готовому файлу.
2. **Изоляция логики бота:** Хэндлеры бота принимают функцию логирования (`logger_callback`), чтобы логи можно было выводить как в консоль (`print`), так и в окно Tkinter (`scrolledtext`).
3. **Безопасная остановка:** Бот должен уметь корректно запускаться и останавливаться программно через вызов методов (без `sys.exit()` внутри обработчиков).

## 3. Функциональные требования (Бизнес-логика)

### 3.1. Калибровка устройства («Донор устройства»)
* Пользователь присылает боту **оригинальное фото со своей камеры как документ/файл**.
* Бот извлекает из структуры EXIF теги:
  * `0th: Make` (Производитель, например, `Apple`, `Samsung`);
  * `0th: Model` (Модель устройства, например, `iPhone 15 Pro`, `SM-S918B`).
* Считанные параметры сохраняются в профиле текущего пользователя (`user_id`).
* Если фото не содержит тегов или пользователь еще не отправил фото-донор, по умолчанию используется пресет: `Make = "Apple"`, `Model = "iPhone 15 Pro"`.
* Бот отправляет уведомление: `«Устройство успешно считано и зафиксировано: [Make] [Model]»`.

### 3.2. Выбор целевой геолокации
* Команда `/geo` или инлайн-меню вызывают двухуровневый выбор (Страна ➔ Город).
* Предустановленный список координат:
  * **Норвегия (🇳🇴):**
    * Тронхейм (`lat: 63.4305, lon: 10.3951`, ISO-6709: `+63.4305+010.3951/`) — *город по умолчанию*.
    * Осло (`lat: 59.9139, lon: 10.7522`, ISO-6709: `+59.9139+010.7522/`)
    * Берген (`lat: 60.3913, lon: 5.3221`, ISO-6709: `+60.3913+005.3221/`)
  * **США (🇺🇸):**
    * Нью-Йорк (`lat: 40.7128, lon: -74.0060`, ISO-6709: `+40.7128-074.0060/`)
    * Майами (`lat: 25.7617, lon: -80.1918`, ISO-6709: `+25.7617-080.1918/`)
    * Лос-Анджелес (`lat: 34.0522, lon: -118.2437`, ISO-6709: `+34.0522-118.2437/`)
  * **Канада (🇨🇦):**
    * Торонто (`lat: 43.6532, lon: -79.3832`, ISO-6709: `+43.6532-079.3832/`)
    * Ванкувер (`lat: 49.2827, lon: -123.1207`, ISO-6709: `+49.2827-123.1207/`)
    * Монреаль (`lat: 45.5017, lon: -73.5673`, ISO-6709: `+45.5017-073.5673/`)
* При выборе города бот сохраняет привязку к `user_id` и выводит подтверждение.

### 3.3. Обработка входящих документов (`F.document`)
Бот принимает контент **исключительно как файл (Document)**, игнорируя сжатые фото/видео, чтобы гарантировать отсутствие вмешательства компрессии Telegram.

#### А. Обработка изображений (JPEG / JPG):
1. Очистка старых GPS-данных и авторских тегов.
2. Преобразование координат выбранного города в рациональные дроби EXIF GPS (DMS: градусы, минуты, секунды).
3. Инъекция тегов:
   * `GPS: GPSLatitudeRef`, `GPSLatitude`, `GPSLongitudeRef`, `GPSLongitude`;
   * `0th: Make` (из донора пользователя);
   * `0th: Model` (из донора пользователя);
   * `0th: DateTime` и `Exif: DateTimeOriginal` (текущее время съемки);
   * `0th: Software` = `"Camera"`.
4. Если входной файл PNG/WEBP — автоматическая конвертация в RGB JPEG перед сохранением.

#### Б. Обработка видео (MP4 / MOV):
1. **Валидация длительности:** вызов `ffprobe` для проверки хронометража.
   * Если длительность **> 16.0 секунд** — процесс прерывается, пользователю выводится сообщение об ошибке: `«Видео слишком длинное (X сек). Лимит: до 15-16 секунд»`.
2. **Инъекция метаданных:** вызов `ffmpeg` в асинхронном подпроцессе:
   * Флаг `-map_metadata -1` (полная очистка старых тегов контейнера).
   * Флаг `-metadata location="[ISO-6709]"` и `-metadata location-eng="[ISO-6709]"`.
   * Флаг `-metadata make="[Make]"` и `-metadata model="[Model]"`.
   * Флаг `-metadata creation_time="[ISO_TIMESTAMP]"`.
   * Флаги потокового копирования: `-c:v copy -c:a copy` (**строго без перекодирования** для максимальной скорости и сохранения качества).
3. Отправка готового файла с исходным именем и подписью с подтверждением примененных гео и модели.

## 4. Этапы разработки (Roadmap)

### Этап 1: Создание чистого бота (v1.0)
* **Цель:** Полностью рабочий бот в консоли.
* **Задачи для агента:**
  1. Реализовать файловую структуру:
     * `engine/geo_data.py` — координаты и список городов.
     * `engine/exif_worker.py` — парсинг донора, конвертация координат DMS, запись EXIF.
     * `engine/video_worker.py` — обертка над `ffprobe` (проверка длительности) и `ffmpeg` (stream copy).
     * `bot/handlers.py` — хэндлеры `/start`, `/geo`, колбэки городов, прием документов.
     * `main.py` — запуск через `asyncio.run(dp.start_polling(bot))` с чтением токена из `.env` или переменной.
  2. Протестировать на тестовых медиафайлах:
     * Считывание Make/Model;
     * Запись координат Норвегии/Тронхейма;
     * Отклонение видео длительностью > 16 секунд.

### Этап 2: Графический интерфейс и компиляция в Windows EXE (v2.0)
* **Цель:** Автономное настольное приложение без необходимости запускать Python вручную.
* **Задачи для агента:**
  1. Создать модуль GUI `gui/app_window.py` на базе `tkinter` и `tkinter.ttk`:
     * Поле ввода Telegram Bot Token с маскированием (`*`) и кнопкой показа;
     * Кнопка «Сохранить токен» (запись в локальный `bot_config.json`);
     * Кнопки «▶️ Включить бота» и «⏹️ Отключить бота»;
     * Индикатор статуса («ОТКЛЮЧЕН» [красный] / «АКТИВЕН» [зеленый]);
     * Текстовая консоль логов (`scrolledtext.ScrolledText`) с перенаправлением логов бота.
  2. Реализовать запуск `aiogram` в отдельном системном потоке (`threading.Thread` + `asyncio.new_event_loop`), чтобы GUI не блокировался.
  3. Реализовать корректное разрешение путей к ресурсам (`get_resource_path`) с поддержкой `sys.frozen` для PyInstaller.
  4. Создать `build.bat` для автоматической сборки:
     * Команда: `pyinstaller --noconfirm --onedir --windowed --name "MetadataBot" app.py`
  5. Организовать поставку `ffmpeg.exe` и `ffprobe.exe` рядом с итоговым `.exe`.

## 5. Требования к коду и безопасности

1. **Очистка буфера:** Все входящие и исходящие файлы в каталоге `temp/` должны гарантированно удаляться в блоке `finally` сразу после отправки или при ошибке.
2. **Отсутствие зависаний:** Запрещены синхронные блокирующие вызовы (например, `subprocess.run` в основном потоке asyncio). Все вызовы внешних утилит должны выполняться через `asyncio.create_subprocess_exec`.
3. **Хранение настроек:** Конфигурационный файл `bot_config.json` не должен содержать ничего, кроме токена бота. Настройки пользователей хранятся в оперативной памяти (словарь `user_settings`) во избежание разрастания базы на диске.
4. **Универсальность путей:** Использовать `os.path.join()` для совместимости с путями Windows.

## 6. Критерии приемки (Definition of Done)

* [ ] **v1.0 (CLI):**
  * Бот успешно запускается из `main.py` по токену.
  * При отправке фото со смартфона бот выводит точное название бренда и модели.
  * Выбор `/geo` сохраняет город Тронхейм (Норвегия) по умолчанию.
  * Видео > 16.5 сек отклоняется без обработки.
  * Обработанные файлы содержат реальные GPS-координаты и открываются на картах Apple Photos / Google Photos.
* [ ] **v2.0 (EXE):**
  * Запуск `MetadataBot.exe` на чистой виртуальной машине Windows без установленного Python.
  * Окно GUI открывается без всплывающего черного окна командной строки (`--windowed`).
  * При нажатии «Включить бота» статус меняется на «АКТИВЕН», в логах появляется запись о подключении.
  * Бот успешно накладывает теги на видео с использованием лежащих рядом `ffmpeg.exe` и `ffprobe.exe`.
